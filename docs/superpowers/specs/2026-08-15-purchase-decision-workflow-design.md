# 購入判断ワークフロー拡張 設計

## 目的と境界

既存の結果表を「監視結果の確認」から、継続利用できる購入判断ワークスペースへと拡張し、以下の7つを完全に実装します：閲覧状態・価格変化・シリーズ絞り込み・スペック信頼度・行内詳細・おすすめ順の説明・24時間の変化マーク。

制約：

- バックグラウンドとページ更新は引き続き10分ごと。ポーリング・ブラウザページ・Mercariリクエストは追加しない。
- サードパーティ依存・データベース・常駐プロセスは追加しない。
- ページは静的 `results.html` のまま。バックグラウンドデータは `results.json` に書き込み、個人の閲覧状態は現在のブラウザの `localStorage` にのみ保存。
- 履歴データには固定上限を持たせ、長期間の実行でファイルやメモリが際限なく増えないようにする。

## 方針の比較

### 方針 A：結果ファイルに軽量履歴を保存し、ブラウザに個人状態を保存（採用）

バックグラウンドは価格またはいいね数が変化したときだけ、各商品の定長履歴配列へ記録を追加。ページはこれらのフィールドを読んでトレンドと変化マークを生成。未確認・ウォッチ・確認済み・無視は個人操作であり、結果ファイルへ書き戻さないため、ローカルサービスや並行書き込みを増やさない。

利点は追加リクエストなし・再起動後も価格履歴が残る・静的ページをそのままダブルクリックで開けること。代償として閲覧状態は現在のブラウザのみに追従します。

### 方針 B：全履歴をブラウザに保存

実装は簡単だが、ページを開いたときだけ価格を比較できるため、バックグラウンド実行中の変化を取りこぼす。ブラウザを変えるとすべて失われ、継続監視の用途に合わない。

### 方針 C：ローカル API とデータベースを追加

ブラウザを越えて全状態を保存できるが、常駐サービス・ポート・依存・リソース消費が増え、「静かに動作する」という現在の制約に合わない。

## データモデルとバックグラウンド処理

独立モジュール `result-history.mjs` を新設し、履歴のマージと読み取りのみを担当させ、`monitor.mjs` の責務が肥大化しないようにします。

各結果は最大12個の異なる値の観測点を保持：

```json
{
  "firstSeenAt": "2026-08-14T08:02:09.347Z",
  "priceHistory": [{ "value": 58000, "at": "2026-08-14T08:02:09.347Z" }],
  "likeHistory": [{ "value": 5, "at": "2026-08-15T05:18:00.000Z" }]
}
```

- `firstSeenAt` は既存の `state.seen[id].seenAt` を優先。旧結果は滑らかに移行でき、更新後にすべて「新着」と誤表示されない。
- 履歴は値が変わったときのみ追加。同一価格・同一いいね数の再確認では JSON を増やさない。
- 旧結果に履歴がない場合は、`state.seen`・旧結果値・現在の観測値でベースラインを確立。
- `recordResult` と `recordLiveResult` は同じ履歴マージ関数を呼ぶ。問い合わせ頻度とページ数は変わらない。
- 書き込みは既存の結果ロックを通し、並行安全性を維持。

## スペック信頼度とおすすめ順

結果ページに、メモリ・ストレージのスペックがタイトルと一致するかを判定する純関数を追加：

- `スペック矛盾`：タイトルが検出結果と異なるメモリ・ストレージを明記。その商品は「通知条件合致」と表示しない。
- `タイトル確認`：タイトルに 32GB・512GB/1TB・SSD が明記され、検出結果と一致。
- `詳細確認`：バックグラウンドで対象スペックを確認済みだが、タイトルに全スペックが明記されていない。
- `情報不足`：上記の結論を導けない。

おすすめ順は固定：

1. 通知条件合致かつスペック矛盾なし。
2. スコアが高い順。
3. 価格が安い順。
4. 直近の確認日時が新しい順。

ページの「おすすめ順」の横に説明ボタンを置き、ホバーまたはフォーカスで完全なルールを表示。上部の最有力候補と既定のテーブル順は同じ比較関数を使用し、2つの領域で結論が食い違わないようにします。

## ページ構造と操作

### ビジュアル方針

現在のベージュ・金茶・緑の落ち着いたワークベンチ風を維持。新機能は1本のコンパクトなコントロールバー・少数の文字ラベル・行内展開でまかない、カード壁や装飾アニメーションは増やさない。

### 内容計画

1. 上部の状態と指標は引き続き監視の概要を担当。
2. 最有力候補が第一の選択肢を示す。
3. コントロールバーにシリーズと閲覧状態の絞り込みを追加。
4. テーブルの主行には判断に必要な情報だけを表示し、完全な根拠は行内詳細へ。

### 操作方針

- 絞り込み・ソート・展開・閲覧状態の変化には 120〜180ms の色または高さの遷移を使用。
- `prefers-reduced-motion` を尊重し、ユーザーがアニメーションを無効にしているときは遷移しない。
- 自動カルーセル・常時アニメーション・装飾的な動きは追加しない。

### シリーズと閲覧状態の絞り込み

- シリーズのプルダウンは現在の結果の `seriesId` / `seriesLabel` から自動生成。既定は「全シリーズ」。
- 閲覧状態は `mercari-laptop-monitor-triage-v1` に保存：既定は未確認。商品リンクをクリックすると自動で確認済みに。詳細内で未確認・ウォッチ・無視に設定可能。
- 既定の「アクティブ商品」は無視を非表示。未確認・ウォッチ・無視・すべてに切り替え可能。
- 検索・上部クイックフィルター・シリーズ絞り込み・閲覧状態絞り込みが同時に効き、それぞれの選択を記憶。

### 行内詳細

各商品の主行に「詳細」ボタンを設け、商品セル内で展開。新しいテーブル行を作らないため、ソートと絞り込みを壊しません。

展開内容：

- スペック信頼度とその根拠。
- 完全な判定理由。
- 元の商品状態。
- 初回発見・出品日時・最終確認日時。
- 未確認・ウォッチ・無視の3つの操作ボタン。

### 価格と変化マーク

- 価格セルは、前の異なる価格がある場合に `↓¥5,000` または `↑¥5,000` を表示し、ホバーで前値と変化時刻が見える。
- 商品タイトルの前に最大3種の24時間マーク：`新着`・`値下げ`・`いいね +N`。
- 上部の「24H 新上架」を「24H 変動あり」に変更し、上記いずれかの変化をフィルター。出品日時は引き続き保持するため、新規出品の情報を失いません。
- 変化が24時間を超えると短期マークは表示しないが、価格履歴は保持され、詳細で直近の変化を確認できます。

## フォールトトレランスと互換性

- 履歴なし・シリーズなし・いいね数なし・旧版結果のいずれも明確なフォールバック文言を使い、ページ描画を妨げない。
- 壊れた `localStorage` データは無視して既定状態に戻す。
- 無視状態は本機のページ表示のみを変え、`results.json` の商品は削除しない。
- すべての動的テキストは引き続き HTML エスケープ。ボタンは `aria-expanded`・`aria-pressed`・可視フォーカスを使用。
- ページ書き換えや F5 の後も、ソート・検索・シリーズ絞り込み・閲覧絞り込み・個人状態が復元される。

## テストと受入

1. `result-history.mjs`：初回ベースライン確立・同値で追加しない・変化で追加・最大12件・旧データ移行をテスト。
2. `results-page.mjs`：メモリ/ストレージ矛盾・信頼度・価格トレンド・24時間マーク・おすすめ比較関数をテスト。
3. 描画テスト：絞り込みコントロール・詳細内容・変化ラベル・おすすめ説明・ARIA・エスケープの存在を確認。
4. 内蔵スクリプト構文テスト：生成 HTML が実行可能であることを保証。
5. 完全な `npm test` と `npm run check`。
6. 実ブラウザ受入：シリーズ絞り込み・状態保存・無視の非表示・行内展開・ソート復元・狭画面レイアウト。テスト後は一時ブラウザとサーバーを閉じる。

## 成功基準

- 7つの機能がすべて同じ結果ページで使える。
- バックグラウンドは既存の単一 Node プロセスのままで、ポーリング間隔は10分を維持。
- 連続する同一チェックで履歴配列が肥大しない。
- ユーザーは Mercari を開かずに、変化・信頼度・次の処理状態を判断できる。
