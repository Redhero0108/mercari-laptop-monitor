# 购买决策工作流升级设计

## 目标与边界

把现有结果表从“查看监测结果”升级为可持续使用的购买决策工作区，完整实现以下七项：浏览状态、价格变化、系列筛选、规格可信度、行内详情、推荐顺序说明和 24 小时变化标记。

约束如下：

- 后台和页面刷新仍为每 10 分钟，不新增轮询、浏览器页面或 Mercari 请求。
- 不新增第三方依赖、数据库或常驻进程。
- 页面继续由静态 `results.html` 工作；后台数据写入 `results.json`，个人浏览状态仅保存在当前浏览器 `localStorage`。
- 历史数据必须有固定上限，避免长期运行导致文件和内存持续增长。

## 方案比较

### 方案 A：结果文件保存轻量历史，浏览器保存个人状态（采用）

后台只在价格或收藏数发生变化时，向每件商品的定长历史数组追加记录；页面读取这些字段生成趋势和变化标记。未看、关注、已看和忽略属于个人操作，不回写结果文件，避免增加本地服务和并发写入。

优点是没有额外请求、重启后价格历史仍存在、静态页面依然可以双击打开。代价是浏览状态只跟随当前浏览器。

### 方案 B：所有历史都保存在浏览器

实现简单，但只有打开页面时才能比较价格，错过后台运行期间的变化；更换浏览器后全部丢失，不满足持续监测用途。

### 方案 C：增加本地 API 与数据库

可以跨浏览器保存所有状态，但会新增常驻服务、端口、依赖和资源占用，不符合当前“安静运行”的约束。

## 数据模型与后台流程

新增独立模块 `result-history.mjs`，只负责合并和读取历史，避免继续扩大 `monitor.mjs` 的职责。

每个结果最多保存 12 个不同值的观察点：

```json
{
  "firstSeenAt": "2026-08-14T08:02:09.347Z",
  "priceHistory": [{ "value": 58000, "at": "2026-08-14T08:02:09.347Z" }],
  "likeHistory": [{ "value": 5, "at": "2026-08-15T05:18:00.000Z" }]
}
```

- `firstSeenAt` 优先使用既有 `state.seen[id].seenAt`，旧结果可平滑迁移，不会在升级后全部误标为新发现。
- 历史只在数值改变时追加；同一价格或收藏数的重复检查不扩充 JSON。
- 旧结果没有历史时，使用 `state.seen`、旧结果值和当前观察值建立基线。
- `recordResult` 与 `recordLiveResult` 统一调用历史合并函数；查询频率和页面数量均不变化。
- 写入仍经过既有结果锁，保持并发安全。

## 规格可信度与推荐顺序

结果页新增纯函数判断内存和存储规格是否与标题一致：

- `规格冲突`：标题明确写出与检测结果不同的内存或存储，禁止显示为“符合提醒”。
- `标题确认`：标题明确包含 32GB、512GB/1TB 与 SSD，且和检测结果一致。
- `详情确认`：后台确认目标规格，但标题没有完整写出全部规格。
- `信息不足`：无法形成以上结论。

推荐顺序固定为：

1. 符合提醒且没有规格冲突；
2. 分数从高到低；
3. 价格从低到高；
4. 最近检查时间从新到旧。

页面“推荐顺序”旁显示说明按钮，悬停或聚焦即可看到完整规则。顶部最佳候选与默认表格顺序使用同一比较函数，避免两个区域结论不一致。

## 页面结构与交互

### 视觉主张

保持当前米白、金棕、绿色的克制工作台风格；新增能力通过一条紧凑控制栏、少量文字标签和行内展开承载，不增加卡片墙或装饰动画。

### 内容计划

1. 顶部状态与指标继续负责监测概览。
2. 最佳候选继续给出第一选择。
3. 控制栏新增系列和浏览状态筛选。
4. 表格主行只显示做决定所需信息，完整依据放进行内详情。

### 交互主张

- 筛选、排序、展开和浏览状态变化使用 120–180ms 的颜色或高度过渡。
- 尊重 `prefers-reduced-motion`，用户关闭动画时不执行过渡。
- 不增加自动轮播、持续动画或装饰性运动。

### 系列与浏览状态筛选

- 系列下拉选项由当前结果中的 `seriesId` / `seriesLabel` 自动生成，默认“全部系列”。
- 浏览状态保存在 `mercari-laptop-monitor-triage-v1`：默认未看；点击商品链接自动记为已看；详情中可设为未看、关注或忽略。
- 默认“活跃商品”隐藏忽略项；可切换未看、关注、忽略或全部。
- 搜索、顶部快捷筛选、系列筛选和浏览状态筛选同时生效，并分别记住用户选择。

### 行内详情

每个商品主行提供“详情”按钮，在商品单元格内展开，不新建表格行，因此不会破坏排序和筛选。

展开内容包含：

- 规格可信度及来源说明；
- 完整判断理由；
- 原始商品状态；
- 首次发现、发布时间、最后检查时间；
- 未看、关注、忽略三个操作按钮。

### 价格与变化标记

- 价格单元格在存在前一不同价格时显示 `↓¥5,000` 或 `↑¥5,000`，悬停可见前值和变化时间。
- 商品标题前最多显示三种 24 小时标记：`新发现`、`降价`、`收藏 +N`。
- 顶部原“24H 新上架”改为“24H 有变化”，筛选任一上述变化；发布时间仍保留，用户不会失去新上架信息。
- 变化超过 24 小时后不再显示短期标记，但价格历史仍保留并可在详情中查看最近一次变化。

## 容错与兼容

- 无历史、无系列、无收藏数或旧版结果都使用明确降级文案，不阻止页面渲染。
- 损坏的 `localStorage` 数据被忽略并回到默认状态。
- 忽略状态只改变本机页面显示，不会删除 `results.json` 中的商品。
- 所有动态文字继续经过 HTML 转义；按钮使用 `aria-expanded`、`aria-pressed` 和可见焦点。
- 页面重写和 F5 后，排序、搜索、系列筛选、浏览筛选与个人状态继续恢复。

## 测试与验收

1. `result-history.mjs`：测试首次建立基线、相同值不追加、变化追加、最多 12 条和旧数据迁移。
2. `results-page.mjs`：测试内存/存储冲突、可信度、价格趋势、24 小时标记和推荐比较函数。
3. 渲染测试：确认筛选控件、详情内容、变化标签、推荐说明、ARIA 与转义存在。
4. 内嵌脚本语法测试：保证生成 HTML 可执行。
5. 完整 `npm test` 与 `npm run check`。
6. 真实浏览器验收：系列筛选、状态保存、忽略隐藏、行内展开、排序恢复和窄屏布局；测试结束后关闭临时浏览器与服务器。

## 成功标准

- 七项功能全部可在同一结果页使用。
- 后台仍只有一个既有 Node 进程，轮询间隔保持 10 分钟。
- 连续相同检查不会扩大历史数组。
- 用户能在不打开 Mercari 的情况下判断变化、可信度和下一步处理状态。
