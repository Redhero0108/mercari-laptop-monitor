# 结果页决策效率改造设计

## 目标

在保留现有米金色视觉识别的前提下，让用户更快判断“是否值得点开”，并避免标题规格与检测规格不一致时出现误导性的绿色提醒。

## 已选方案

采用现有单文件生成器内的渐进式重排，不引入前端框架或新依赖。

- 方案 A（已选）：重排现有信息层级并补充少量纯函数。改动集中、资源占用不变、能够沿用现有测试。
- 方案 B：完全重写为组件化前端。扩展性更高，但会增加依赖和维护成本，不符合当前轻量目标。
- 方案 C：只调整颜色和间距。风险最低，但无法解决判断效率与规格矛盾问题。

## 视觉与内容

**视觉论点：** 温和的米白工作台配合单一金色强调，信息紧凑、沉稳、可信，不增加装饰性动画。

**内容计划：** 顶部品牌与后台状态用于定位；紧凑指标条同时承担快捷筛选；“当前最佳候选”承担首要行动；搜索工具条承担进一步缩小结果；表格承担比较与打开商品。

**交互论点：** 点击指标即可筛选，排序列提供明确激活态，商品行只保留轻量悬停反馈；不增加轮询、滚动动效或持续计时器。

## 功能设计

1. 标题明确出现非 32GB 内存、检测原因却含“32GB内存”时，显示“标题规格与检测结果不一致 · 需要人工确认”。该商品不进入页面的“符合提醒”数量、筛选或最佳候选。
2. 在价格后增加独立“判断”列；价格列同时显示预算内或超预算差额。
3. 四张大统计卡改为一行紧凑、可点击的筛选指标，并新增“预算内 ≤ ¥70,000”。
4. “BEST SIGNAL”改为显眼的“当前最佳候选”横条，显示等级、价格、预算状态和完整可点击标题。
5. 页面最大宽度收敛，商品列自适应展开，标题最多两行；小屏逐步隐藏低优先级日期、收藏和状态列。
6. 新增独立预算筛选，使用当前 `maxPriceYen` 配置，默认值为 ¥70,000。
7. 时间统一为 `MM-DD HH:mm`，完整 JST 时间保留在 `title`；状态改为“后台正常｜上次检查｜下次约”，不增加定时刷新请求。
8. 实用文案统一为中文，保留 Mercari 原生名词说明，例如“收藏数（いいね）”；辅助标签最小字号提高到 12px。

## 数据流与边界

- `results-page.mjs` 从已有 entry 标题、原因、价格和时间推导页面状态，不修改监测数据文件。
- 规格矛盾仅影响前端资格展示，后台筛选与提醒逻辑保持不变。
- 预算筛选继续与搜索条件组合生效，并存储于现有本地筛选设置。
- HTML 仍通过 meta refresh 每 10 分钟刷新，后台状态脚本仍只在页面加载时读取一次。

## 验证

- 单元测试覆盖规格矛盾、预算筛选、独立判断列、紧凑指标、最佳候选、统一文案、短时间与八列表格。
- 运行完整 `npm test` 与 `npm run check`。
- 使用本地生成的 HTML 做桌面和窄屏视觉截图核对。
