# 結果ページの判断効率改善 設計

## 目的

既存のベージュ系のビジュアルアイデンティティを保ちつつ、「クリックする価値があるか」をより速く判断できるようにし、タイトルのスペックと検出スペックが一致しない場合に誤解を招く緑の通知表示を防ぐ。

## 採用した方針

既存の単一ファイル生成器の中での段階的な再構成を採用し、フロントエンドフレームワークや新しい依存関係を導入しない。

- 方針 A（採用）：既存の情報階層を再構成し、少量の純関数を追加。変更は集中し、リソース消費は変わらず、既存テストを継続利用できる。
- 方針 B：コンポーネント化されたフロントエンドへ完全書き換え。拡張性は高いが依存・保守コストが増え、現在の軽量目標に合わない。
- 方針 C：色と余白のみ調整。リスクは最小だが、判断効率とスペック矛盾の問題は解決できない。

## ビジュアルと内容

**ビジュアル論点：** 穏やかなベージュのワークベンチと単一のゴールド強調。情報はコンパクトで落ち着いて信頼感があり、装飾的なアニメーションは増やさない。

**内容計画：** 上部のブランドとバックグラウンド状態は位置確認用。コンパクトな指標バーはクイックフィルターを兼ね、「現在の最有力候補」が最初のアクション。「検索ツールバー」で結果を絞り込み、表で比較と商品ページへの遷移を行う。

**操作論点：** 指標クリックでフィルター、ソート列には明確なアクティブ状態、商品行には軽いホバーだけを残す。ポーリング・スクロール演出・常時タイマーは追加しない。

## 機能設計

1. タイトルに 32GB 以外のメモリが明記されているのに、検出理由が「32GB内存」を含む場合は「タイトルスペックと検出結果が不一致・要確認」を表示。この商品は「通知条件合致」件数・フィルター・最有力候補に入らない。
2. 価格の後ろに独立した「判定」列を追加。価格列は予算内または予算超過の差額も表示。
3. 4つの大きな統計カードを、1行のコンパクトでクリック可能なフィルター指標に変更し、「予算内 ≤ ¥70,000」を追加。
4. 「BEST SIGNAL」を目立つ「現在の最有力候補」バーに変更し、ランク・価格・予算状態・クリック可能な完全タイトルを表示。
5. ページの最大幅を抑え、商品列は適応的に伸長し、タイトルは最大2行。狭い画面では優先度の低い日付・いいね・状態列を段階的に非表示。
6. 独立した予算フィルターを追加。現在の `maxPriceYen` 設定を使用し、既定値は ¥70,000。
7. 時刻は `MM-DD HH:mm` に統一し、完全な JST 時刻は `title` に保持。状態は「バックグラウンド正常｜前回チェック｜次回目安」に変更し、定時更新リクエストは増やさない。
8. 実用文案は中国語に統一し、Mercari 固有の語は「收藏数（いいね）」のように説明を添えて保持。補助ラベルの最小フォントサイズを12pxに引き上げ。

## データフローと境界

- `results-page.mjs` は既存の entry のタイトル・理由・価格・時刻からページ状態を導出し、監視データファイルを変更しない。
- スペック矛盾はフロントエンドの表示資格のみに影響し、バックグラウンドのフィルターと通知ロジックは変更しない。
- 予算フィルターは検索条件と組み合わせて動作し、既存のローカルフィルター設定に保存。
- HTML は引き続き meta refresh で10分ごとに更新し、バックグラウンド状態スクリプトはページ読み込み時のみ一度だけ読み取る。

## 検証

- ユニットテストがスペック矛盾・予算フィルター・独立判定列・コンパクト指標・最有力候補・統一文案・短時間形式・8列テーブルをカバー。
- 完全な `npm test` と `npm run check` を実行。
- ローカル生成 HTML をデスクトップと狭画面のビジュアルスクリーンショットで確認。
