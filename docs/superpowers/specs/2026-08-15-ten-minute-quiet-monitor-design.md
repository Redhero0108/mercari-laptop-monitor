# 10分の静かな監視 設計

## 目的

ユーザーは `open-results.cmd` をダブルクリックするだけです。起動ウィンドウはできるだけ早く消えて `results.html` を開きます。隠しバックグラウンド監視は継続しますが、新商品の検索・既存商品の資料更新・結果ページの自動リロードはすべて10分に1回に統一します。待機中に結果ページを10秒ごとにポーリングしたり、モニターが高頻度でハートビートファイルを書き込んだりしないようにします。

## 確定した操作

1. `open-results.cmd` をダブルクリックすると、既存の `start-background.ps1` が隠し監視を冪等に起動。監視が既に動いていれば重複起動しない。
2. `results.html` は既定ブラウザで開かれ、CMDウィンドウは終了。
3. 監視は起動後すぐ最初のチェックを実行し、以後10分ごとに新商品を検索。既存商品の価格・いいね・状態・在庫は10分ごとに更新。
4. 結果ページは600秒ごとに自動リロード。検索・絞り込み・並び順は `localStorage` でリロード間も保持。
5. ページに手動同期ボタンはなく、`monitor-status.js` を10秒ごとに動的ロードもしない。

## 実装境界

- `config.json` の `pollMinutes` を5から10に変更。`likesRefreshMinutes` は10のまま。
- `monitor.mjs` の既定 `pollMinutes` と無効設定のフォールバック値も10に揃え、設定欠落時に5分へ戻らないようにする。
- `results-page.mjs` のHTML自動更新周期を300秒から600秒に変更し、ヘッダー説明も更新。
- ページ読み込み時に `monitor-status.js` を一度だけ読み取り、10秒 `setInterval` を削除。
- 監視状態は起動時・フェーズ変化・チェック完了時・停止時のみ書き込む。待機中の20秒ごとファイル書き込みハートビートタイマーを削除。ページ側の状態切れ判定ウィンドウは1周期より大きくし、通常待機中に誤ってオフライン表示しない。
- `start-monitor.cmd`・`stop-background.cmd`・明示的な1回チェックモードの既存機能は維持。依存を追加せず、絞り込み・通知・商品データ形式も変更しない。

## 異常とリソース動作

- `start-background.ps1` は引き続き `monitor.pid` で重複起動を防止。
- バックグラウンドのチェック失敗はログを記録し、次の10分周期で再試行。
- ページの自動更新はローカルの `results.html` のみ再読み込みし、Mercari へ個別リクエストはしない。Mercari へのネットワークアクセスはバックグラウンドチェックのみが行う。
- バックグラウンドプロセスが予期せず終了した場合、状態は15分以上更新がないとオフライン表示になる。ユーザーは `open-results.cmd` を再ダブルクリックして復旧できる。

## 検証

- ページ描画テストで `content="600"` が存在し、10分説明が存在し、10秒ポーリングが存在しないことを検証。
- 設定/ソーステストで検索と既存商品の更新周期がともに10分であり、高頻度ハートビート `setInterval` が存在しないことを検証。
- PowerShell 解析テストで起動/停止スクリプトが Windows PowerShell 5.1 と互換であることを確認。
- 完全な `npm test` と `npm run check` を実行し、ローカルの `results.html` を再生成して最終成果物を確認。
