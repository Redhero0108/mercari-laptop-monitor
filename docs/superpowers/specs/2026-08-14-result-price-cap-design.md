# Mercari 结果价格上限设计

## 目标

监控结果中不再保留价格达到或超过 100,000 日元的商品。价格 99,999 日元及以下仍可进入结果列表，并继续接受现有的系列、内存、SSD、CPU、商品状态、在售状态和风险关键词检查。

## 与现有提醒线的关系

现有 `maxPriceYen: 95000` 继续作为“是否达到提醒条件”的价格线，不作修改。新增独立的结果列表价格上限，避免把“是否显示”和“是否提醒”混成同一个配置：

- `0～95,000` 日元：可以显示，也可能提醒。
- `95,001～99,999` 日元：可以显示，但不会提醒。
- `100,000` 日元及以上：不显示、不提醒，并从结果记录中剔除。
- 价格无法确认：不因本规则单独删除，但仍不会达到现有提醒条件。

## 配置与实现

在 `config.json` 和监控器默认配置中增加 `maxResultPriceYen: 99999`。

统一的硬过滤函数增加价格判断，并返回稳定的 `price` 拒绝原因。新品详情检查、旧商品资料补查、实时资料刷新和结果页重新生成全部复用同一规则。这样已经存在的 100,000 日元以上旧记录会在监控器启动或刷新结果页时自动清除。

价格比较使用详情页解析后的整数日元价格；边界为 `price <= maxResultPriceYen`。

## 日志与界面

被剔除时记录中文原因“价格达到或超过10万日元”。由于商品不会进入结果数据，页面无需新增栏目或筛选按钮。

## 测试

回归测试必须覆盖：

- 99,999 日元通过硬过滤。
- 100,000 日元被价格规则拒绝。
- 高价旧结果无法通过结果页过滤。
- 价格未知不会被本规则单独删除。
- 完整测试、Node.js 语法检查和 `git diff --check` 全部通过。

## 安全与范围

程序仍只读取 Mercari 公开商品，不购买商品、不收藏，也不联系卖家。本次不改变五个搜索关键词、轮询间隔或其他硬件筛选条件。
