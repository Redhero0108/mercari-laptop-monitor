# 严格内存与风险过滤设计

## 目标

从搜索录入、提醒和结果页中彻底剔除两类不符合购买要求的商品：标题只标明 16GB、仅表示可以升级到 32GB 的商品，以及存在外观、屏幕、严重故障或锁机风险的商品。

## 过滤规则

- 标题明确包含 `32GB` 时保留。
- 标题明确包含 `16GB×2`、`16GBx2`、`16GB*2` 或 `16GB+16GB` 时按合计 32GB 保留。
- 标题只标明 `16GB`，即使详情或判断理由检测为 32GB，也剔除。
- 标题描述“可升级、可扩展、増設、最大支持 32GB”等能力，但当前规格仍为 16GB，也剔除。
- 判断理由包含“外观或屏幕有缺陷”时剔除。
- 判断理由包含“严重故障/锁机风险”时剔除。

## 实现方式

在 `laptop-filters.mjs` 的中央硬过滤链中统一判断标题内存冲突和风险理由。新搜索结果在写入前被拒绝，已有结果在生成结果页时被清理，提醒逻辑使用同一过滤结果，避免前端隐藏与后台提醒规则不一致。

标题内存判断封装为纯函数，供新结果评估和已有结果过滤共同使用。风险判断基于现有结构化 `reasons`，不新增依赖或后台进程。

## 测试

- 单独 `16GB` 且详情判定 32GB：拒绝。
- `16GB` 且写明可升级到 32GB：拒绝。
- `16GB×2`、`16GB+16GB`、明确 `32GB`：保留。
- “外观或屏幕有缺陷”：拒绝。
- “严重故障/锁机风险”：拒绝。
- 正常 32GB 商务本：继续通过。

## 运行约束

保持现有 Windows/PowerShell 运行方式、单一后台监控进程和 10 分钟检查周期，不增加依赖或常驻任务。
